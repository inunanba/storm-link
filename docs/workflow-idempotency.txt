What changed against a9ccda0
- Storm.Process.RequestReview(rid) runs under the storm lock only while the stored marker is PENDING/SEND_FAILED.
  Before sending it looks up an existing task for the stored storm id (Storm.Review.FindTask: persisted
  TaskRequest first, then delivered TaskResponse, exact subject match on the storm id). Found -> marker REQUESTED, no send.
- A resend of a FINAL storm returns the stored result unchanged and runs the same idempotent RequestReview,
  so a stop between the FINAL commit and the task send is recovered by the next resend.
- FINAL is answered only after the journal is flushed (SynchCommit is off by default; a kill a few seconds
  after a commit could otherwise lose that commit).
- Storm.ReviewOperation (subclass of EnsLib.Workflow.Operation, same config name/role Storm.Review): when Ens
  redelivers the same TaskRequest after an unclean stop, the task already created for it is reused and only the
  deferred-response token is re-bound. Without this the stock operation created a second task for one request
  (observed in an earlier run: 2 TaskResponse rows for one TaskRequest).
- init.script recovers a Troubled production after an unclean stop before starting it (before this the
  container could not come back after a kill: STORM_START_FAILED).
- Test-only stop hooks live in IRISTEMP (^IRIS.Temp.StormTest, not journaled, empty after restart).
